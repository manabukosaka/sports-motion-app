# MVP V1.0 対象動作と現場検証仕様

## 1. V1.0 の対象動作

- **野球投球（速球）**：骨盤・胸郭から投球腕へつながる運動連鎖と、肩・肘の高速な動きを捉える。
- **ランニング（地上・トレッドミル）**：同側の接地から次の接地までの周期で、下肢の関節運動と左右差を捉える。
- **垂直跳び（CMJ）・ドロップ垂直跳び（DVJ）**：CMJ は反動を使った跳躍の遂行、DVJ は台から降りた直後の着地制御と反発を観察する。ACL 傷害リスクに関連する着地所見は指導用の運動学的スクリーニングに限る。[DVJ の前向き研究](https://pubmed.ncbi.nlm.nih.gov/26867936/)

3領域とも査読済みの計測研究が蓄積されており、動作条件をそろえた文献比較を設計できる。規範値・DOI の収集と比較可能性の判定は [Issue #3](https://github.com/manabukosaka/sports-motion-app/issues/3) で行う。[投球](https://pmc.ncbi.nlm.nih.gov/articles/PMC6512154/)・[ランニング](https://pubmed.ncbi.nlm.nih.gov/18460996/)・[CMJ](https://pubmed.ncbi.nlm.nih.gov/24875041/)・[DVJ](https://pubmed.ncbi.nlm.nih.gov/38042067/)

## 2. 動作別計測仕様

### 共通ルール

- **イベントと正規化**：フレーム番号・実撮影時刻・判定方法（自動／手動）を保存する。動作別の開始・終了イベント間を実時間で線形に 0〜100% へ写像し、中間イベントと速度ピークの順序を保つ。速度は正規化前の実時間から算出する。始点・終点を特定できない試技は正規化比較から外す。
- **指標の定義**：関節角は ISB 推奨を基本とする関節座標系で算出し、軸・回転順序・符号・左右を記録する。下表の面は矢状面（Sagittal）・前額面（Frontal）・水平面（Transverse）を指す。文献比較にはイベント・角度定義・計測条件を照合する。[ISB の標準化文書](https://media.isbweb.org/standards/)・[肩・肘の関節座標系](https://media.isbweb.org/images/documents/standards/isb_jcs_part_ii.pdf)
- **単眼・2カメラ共通**：固定台と十分な照明を使い、開始前から最終イベントまで対象部位を画角内に収める。表の FPS は撮影時の推奨設定で、実撮影タイムスタンプとフレーム欠落を確認する。単眼の距離・速度は実寸スケール、鉛直・進行方向、推定精度を確認できる試技で表示する。
- **2カメラ DLT**：両視点に写る計測体積全体に既知の非共面制御点を配置し、レンズ歪みを補正する。校正と本撮影でカメラ位置・レンズ・ズーム・解像度を固定する。両カメラを同じ FPS に設定し、共通同期信号を収録前後に記録して時刻差・ドリフトを確認する。校正に使わなかった確認点で再投影誤差（`px`）と既知長の再構成誤差（`m`）を記録する。[DLT によるカメラ同期の研究](https://www.sciencedirect.com/science/article/abs/pii/S0021929000001329)
- **座標編集**：低信頼フレームは視認できる `Image2D` 点を修正し、Raw を保持したまま `World3D` と指標を再計算する。遮蔽点は別視点を確認し、両視点で確認できない区間は欠測として扱う。イベント付近の欠測によって値や時刻が確定できない指標は比較から外す。

### 野球投球（速球）

| 項目 | 仕様 |
| :--- | :--- |
| 標準イベント | **Leg Lift**（踏み出し脚の膝が最高）→ **Foot Contact**（踏み出し足が最初に接地）→ **MER**（接地後、リリースまでの投球肩最大外旋）→ **Ball Release**（ボールが投球手を離れた最初のフレーム）→ **MIR**（リリース後の減速局面で投球肩が最大内旋）。Leg Lift を 0%、MIR を 100% とする。 |
| 優先 3D 指標 | **水平面**：骨盤・胸郭の投球方向に対する回旋角（`deg`）、それぞれの最大回旋角速度（`deg/s`）とピーク時刻（`%`）。**水平面に対応する局所軸回旋**：胸郭に対する上腕長軸まわりの内外旋角（`deg`）と最大内旋角速度（`deg/s`）。**矢状面**：接地・MER・リリース時の投球肘屈曲角（`deg`）と最大伸展角速度（`deg/s`）。上腕の軸回旋を識別できる体節モデルで算出する。肩・肘中心だけで回旋を識別できない試技では欠測とする。 |
| 推奨撮影 | **単眼**：投球腕側の真横、`240 fps` を優先。両足、投球腕、リリース直後のボールを収める。**2カメラ DLT**：投球腕側の側方＋投手後方斜め。脚上げから減速までの踏み出し範囲と腕の高さを共通校正体積に含める。 |
| 遮蔽・座標編集 | MER 付近の投球肘・手首の重なり、リリース時の手首・ボールのブレ、減速時の体幹による投球腕の遮蔽。投球側の肩・肘・手首と踏み出し足の足首・つま先を優先して修正し、リリースは映像で確認する。 |

### ランニング（地上・トレッドミル）

| 項目 | 仕様 |
| :--- | :--- |
| 標準イベント | 片脚ごとに **Initial Contact**（足の最初の接地、0%）→ **Mid-Stance**（本仕様では接地から離地までの時間中点）→ **Toe-Off**（足が支持面を離れた最初のフレーム）→ 次の同側 **Initial Contact**（100%）。左右を識別して複数の完全なストライドを記録する。 |
| 優先 3D 指標 | **矢状面**：股・膝の屈伸角、足関節の背屈／底屈角（`deg`）の波形。**前額面**：立脚中の骨盤側方傾斜・股関節内転角（`deg`）。**進行軸**：地上走のストライド長（同側の連続接地点の間隔、`m`）と平均進行速度（ストライド長 ÷ 周期秒、`m/s`）。**時間指標**：両足の接地から求めるケイデンス（`spm`）。トレッドミルはベルト速度（`m/s`）を撮影条件として記録する。 |
| 推奨撮影 | **単眼**：進行方向に対して真横、`120 fps`。地上走は一定ペース区間、トレッドミルはペースが安定した区間を撮る。**2カメラ DLT**：真横＋後方斜め。地上走は両視点で全身が見える区間を校正し、トレッドミルはベルト面を接地面として記録する。走行条件と速度をそろえて比較する。 |
| 遮蔽・座標編集 | 側面ではカメラから遠い側の脚が隠れ、交差時に左右ラベルが入れ替わる。トレッドミルでは手すりが骨盤を隠すことがある。接地・離地付近の踵・つま先・足首、交差時の膝と左右ラベルを優先する。 |

### 垂直跳び（CMJ）・ドロップ垂直跳び（DVJ）

| 項目 | 仕様 |
| :--- | :--- |
| 標準イベント | **CMJ**：**Initiation**（静止立位からの重心下降開始、0%）→ **Peak Flexion**（離地前の左右平均膝屈曲角の最大）→ **Take-off**（両足が離地）→ **Initial Landing Contact**（跳躍後に一方の足が最初に接地）→ **Peak Landing Flexion**（着地後の左右平均膝屈曲角の最初のピーク、100%）。**DVJ**：台から降りた直後の **Initial Landing Contact**（初回接地、0%）→ **Peak Landing Flexion**（同じ定義）→ 反発跳躍の **Take-off**（100%）。反発跳躍後の着地は別イベントとして記録する。 |
| 優先 3D 指標 | **矢状面**：股・膝屈曲角、足関節背屈角（`deg`）を着地時と着地屈曲ピーク時に左右別に取得。**前額面**：同イベントで左右の膝外転（外反）角（`deg`）。**鉛直軸**：CMJ・DVJ 反発時の離地から頂点までの身体重心の上昇量（`m`）と離地時の鉛直速度（`m/s`）。 |
| 推奨撮影 | **単眼**：足元が見える真横、`120 fps` を基本に DVJ は `240 fps` も検証する。**2カメラ DLT**：真横＋正面。台・床・跳躍頂点を共通校正体積に収め、床面と鉛直を定義する。比較時は腕振り条件、DVJ の台高（`m`）と降り方の指示をそろえる。 |
| 遮蔽・座標編集 | 深い屈曲で腕や衣服が股関節を隠し、側面で両膝・足首が重なる。正面も確認し、初回着地と着地屈曲ピークの左右股関節・膝・足首、離地前後のつま先を優先する。 |

## 3. 現場コーチング検証（Phase 0）

部活・クラブのコーチ、選手、トレーナーから計 5〜10 名を募る。3領域それぞれで指導・練習経験者を含める。撮影・閲覧への同意を得た素材またはデモ素材を使い、LINE は検証用トークで送受信する。各参加者には担当動作で普段の操作を再現してもらい、続けて同じ動作の試作画面で課題を実施する。

| 検証項目 | 質問・タスク | 観察・記録 |
| :--- | :--- | :--- |
| 現行ワークフロー | 「直近の指導・練習で、撮影からフィードバックまでどう進めたか」。普段のツールと素材で再現してもらう。 | 工程別の所要時間、ツールの切替、やり直し・断念、選手への伝達で起きた具体的な困り事。 |
| 座標編集の許容度 | 低信頼フレームを探し、ルーペで関節1点を直して、再計算した指標を確認する。「練習中にどこまでなら直すか。いつなら撮り直すか」。 | 所要時間、修正数、補助の有無、誤操作、続行を断念する条件。 |
| 文献比較の理解 | 比較カードと波形を見て、自分の値、比較集団、差の方向、次に確認する動作を説明してもらう。 | 条件・出典の確認、指標と解釈の取り違え、原因の断定や診断と受け取った箇所。 |
| LINE 共有 | 送信側は閲覧相手・期限を指定して要約画像と URL を共有。受信側はアプリ未導入の状態で LINE 内から開き、コーチのコメントを確認する。 | 送受信の完遂、操作の詰まり、リンクが開ける範囲・期限の理解。 |
| 機能優先度 | 座標編集・エビデンス比較・LINE 共有を優先順に並べ、最優先とした理由を具体的な場面で説明してもらう。 | 役割・動作ごとの順位と根拠。観察した行動と本人の申告を区別して記録する。 |

参加者 ID ごとに役割、動作、使用ツール、課題の結果を記録し、項目ごとに実施人数と完遂人数を集計する。

### Gate 0 判定

[開発プロセスの Phase 0](./03-development-process.md) に従い、Product Owner が以下の3条件で Go / Pivot を判断する。

1. 競合比較と差別化仮説が文書化され、現行ツールで解消できない課題を観察・発言の証跡付きで3点以上特定した。
2. ヒアリング結果から V1.0 の対象動作を確認でき、座標編集・エビデンス比較・LINE 共有の優先順位と判断理由を説明できる。
3. Issue #3 で対象動作の査読論文15編以上の入手可能性と、取得する指標の定義を確認した。

全条件を満たせば Phase 1 へ進む。未達時は対象者・動作・機能順位の再検証事項と、Go に必要な追加証跡を記録する。

## 4. モバイル技術スタックの作業仮説

React Native（Expo）を iOS / Android 共通クライアントの第一候補とする。LINE 共有 Web ビューアとは、解析結果・動作イベント・比較レポートの JSON Schema と、そこから生成する TypeScript 型を共有する。共通の試技データで、両クライアントが単位・座標系・イベント時刻を同じように解釈することを確認する。実機評価を [Phase 1 Spike #6](https://github.com/manabukosaka/sports-motion-app/issues/6) で行い、採否と契約を [ADR #26](https://github.com/manabukosaka/sports-motion-app/issues/26) で確定する。

| Spike #6 の検証項目 | 実機で確認すること |
| :--- | :--- |
| `240 fps` 撮影 | iOS / Android の候補端末で実効 FPS、保存時のフレーム時刻・欠落、対応解像度、連続撮影時の発熱を記録する。Expo の標準機能で満たせない場合は開発ビルドでのネイティブ拡張や、対応 FPS・動画取り込みへの切替を比較する。[Expo 開発ビルドとネイティブコード](https://docs.expo.dev/workflow/customizing/) |
| `60 fps` のオーバーレイ・ルーペ | 高速撮影クリップの再生・シーク時の骨格同期と、停止フレームのドラッグ中のルーペ追従を検証する。描画 FPS・フレーム時間・入力から表示までの遅延を測り、補間・再計算は確定操作から結果表示まで5秒以内か確認する。 |

OS・端末・解像度・クリップ・試行回数・計測手順を結果と一緒に残す。アーキテクチャ上の位置付けは [プロダクトデザイン仕様](./02-product-design.md) を参照。
