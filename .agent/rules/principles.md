# Agent Engineering Principles & Domain Invariants

Lauren Tan（`@poteto` / `pstack`）の原則をベースに、本プロジェクト（3次元スポーツ動作解析アプリ）固有の不変条件を統合した判断基準。エージェントは設計・実装・レビュー時の意思決定において、該当原則を明示して適用する。

---

## 1. Core Engineering Principles（`pstack` 準拠）

### P1. Prove It Works（動作を証明せよ）
- 「動くはず」「型チェックが通った」は完了条件にならない。
- 実アプリ・Webビューア・CLI・`biomech-eval` を実際に実行し、観測された出力・数値・ログを完了の根拠とする。

### P2. Fix Root Causes（根本原因を直せ）
- 症状を隠すだけの `try/catch` 握りつぶし、マジックナンバー補正、一時回避パッチを禁止する。
- 実行経路をエントリポイントからトレースし、根本原因を修正する。

### P3. Subtract Before You Add（足す前に引け）
- 新しい抽象化・ヘルパー・依存ライブラリを足す前に、不要なコードを削除し既存構造を単純化できないか必ず確認する。

### P4. Laziness Protocol（最小変更プロトコル）
- 目的を安全に達成する最小の差分を選ぶ。依頼範囲外のフォーマット変更、無関係なリファクタリング、将来用だけの未使用抽象化を混ぜない。

### P5. Model the Domain（ドメインを先にモデル化せよ）
- 実装前にモジュール境界とデータ型（契約スキーマ）を定義する。呼び出し側（Caller）から見て不正な状態を型レベルで表現不能にする。

### P6. Explain the Number（数値を説明せよ）
- 精度（RMSE / 相関係数）、処理速度、メモリ使用量などの数値を報告する際は、必ず **データセット・対象端末/環境・サンプル数・再現コマンド** を添える。

### P7. Sequence Work into Verifiable Units（検証可能な小単位に分割せよ）
- 複数関心事を巨大な1変更にまとめない。独立してテスト・レビュー・ロールバックできる垂直単位で進める。

### P8. Test Behavior, Not Implementation（振る舞いをテストせよ）
- 内部関数呼び出し回数のモック検証に依存しない。公開境界における入出力契約、物理的妥当性、ユーザー操作シナリオを検証する。

### P9. Zero Slop & Minimal Comments
- 自明なコードに対する逐語コメントを書かない。コメントは「外部仕様・論文式・座標系規約など、コード単体では表現できないWhy」のみに限定する。

## 2. Sports Biomechanics Domain Invariants（ドメイン不変条件）

本プロジェクトでは、以下のドメイン制約違反を **重大バグ（P0/P1）** とみなし、可能な限り型と自動テストで機械強制する。

1. **座標系と単位の厳密性**
   - 角度（`deg` / `rad`）、長さ（`m` / `mm` / `px`）、時間（`sec` / `frameIndex`）、座標系（`Image2D` / `Camera3D` / `World3D` / `SegmentLocal3D`）は明確に型またはスキーマ属性で区別する。
   - 関節角度定義は原則として **ISB（International Society of Biomechanics）推奨規格** に準拠し、定義ファイルへ明記する。
2. **解析手法の透明性と再現性**
   - すべての解析結果には `pipeline_version`、`tracker_2d`、`reconstructor_3d`、`filter_params`、`calibration_error`（該当時）をメタデータとして保存する。
   - 同一入力＋同一設定＋同一座標編集履歴からは、許容数値誤差内で決定論的に同一結果を再現できなければならない。
3. **非破壊座標編集（Human-in-the-Loop）**
   - AIまたは古典手法が生成した生データ（Raw）を破壊上書きしない。手動修正は編集レイヤー（Diff/Revision）として管理し、任意時点へのUndoおよび比較を可能にする。
4. **エビデンスの科学的誠実性**
   - 文献統計比較に用いるすべての基準値には、出典（著者・出版年・ジャーナル・DOI・対象属性・サンプル数・計測方式）を必須とする。出典のない推測数値をエビデンスDBに登録しない。
   - アプリ出力はコーチング・分析支援であり、医療診断ではない旨の表現ルールを逸脱しない。
5. **アスリート映像のプライバシー境界**
   - チーム・選手データおよび動画・共有レポートは厳格なテナント分離を行う。共有URLは推測不可能な署名付きトークンと有効期限・アクセス制御を必須とする。
